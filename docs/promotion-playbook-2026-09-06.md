# 자취도우미 초기 홍보 운영안

## 무엇을 참고했나

`cowlr.kr`에서 가져온 것은 색상이나 문구가 아니라 첫 화면의 작동 방식이다.

- 설명보다 검색과 분류를 먼저 보여 준다.
- 한 화면에서 여러 항목을 빠르게 비교한다.
- 정렬 기준을 사용자가 바꿀 수 있게 한다.
- 다음 행동을 각 항목 가까이에 둔다.

자취도우미에는 이를 준비물 검색, 카테고리, 구매 시점 정렬, 판매처 검색으로 바꿔 적용한다. 공식 상품 데이터가 없는 현재는 최저가, 인기순, 실시간 재고를 표시하지 않는다.

## 채널 우선순위

1. 네이버 블로그: `첫 자취 준비물`, `자취 필수품`, `입주 준비물`처럼 문제를 이미 검색하는 사람을 받는다.
2. 디스콰이엇: 제품 자체보다 문제를 발견하고 고친 과정과 필요한 피드백을 공개한다.
3. 직접 사용자 모집: 첫 자취 예정자 또는 자취 1년 이내 사용자 5명에게 링크를 전달하고 화면 공유 없이 혼자 사용하게 한다.
4. GeekNews Show GN: 소비자 유입보다 제품·데이터 구조 피드백을 받는 보조 채널로 사용한다.
5. 인스타그램: 전문 계정과 게시 API 준비 전에는 초안만 만든다. 짧은 화면 녹화가 준비된 뒤 게시한다.

## 14일 실험

- 같은 랜딩 페이지를 유지한다.
- 채널마다 UTM 주소만 다르게 쓴다.
- `home_cta_click / 유입 세션`으로 홈 시작률을 본다.
- `plan_complete / plan_start`로 계획 완주율을 본다.
- `store_link_click / recommend_result_view`로 판매처 이동률을 본다.
- 표본이 작을 때 이탈률 하나로 디자인을 다시 바꾸지 않는다. 사용자 5명의 막힌 지점과 이벤트 누락을 함께 본다.

## 게시 순서와 중단 기준

1. 네이버 블로그 원고 1편을 먼저 발행한다. 검색 유입을 받을 수 있는 제목과 실제 화면 3장을 사용한다.
2. 첫 3일 동안 링크 오류, 모바일 화면, GA4의 `home_cta_click` 수집 여부만 확인한다.
3. 디스콰이엇에는 완성품 홍보보다 문제를 발견하고 고친 과정과 받고 싶은 피드백을 올린다.
4. 첫 사용자 5명에게는 공개 글과 다른 UTM 링크를 전달해 직접 모집과 공개 채널을 구분한다.
5. 14일 동안 홈 제목·구조·핵심 CTA를 다시 바꾸지 않는다. 치명적인 오류만 수정한다.

다음 상황이면 홍보량을 늘리지 않고 제품을 먼저 고친다.

- 방문은 있는데 `home_cta_click`이 거의 없다.
- `plan_start`는 있지만 `plan_complete`가 반복해서 끊긴다.
- 결과를 봐도 `recommendation_decision`이 발생하지 않는다.
- 피드백에서 같은 누락 또는 불필요 항목이 세 번 이상 반복된다.

## 게시용 화면 구성

- 첫 화면: 검색창과 준비물 카드가 함께 보이는 장면
- 계획 설정: 보유품 제외와 생활 조건 선택 장면
- 결과 화면: 지금 필요·조건 확인·나중에와 판매처 버튼이 보이는 장면

실제 최저가, 인기순, AI 맞춤 추천이라는 표현은 상품 데이터 연결 전까지 사용하지 않는다.

## 자동화 범위

자동으로 해도 되는 일:

- 채널별 문구 초안과 UTM 링크 생성
- 오탈자, 금지 주장, 링크 상태 점검
- 최근 측정값을 기준선과 비교한 요약 작성

사람이 확인해야 하는 일:

- 커뮤니티 규칙에 맞는지 확인
- 게시 버튼을 누르기 전 최종 문구 승인
- 댓글과 질문에 직접 답변

초안 생성은 `npm run promotion:build`로 실행한다. 결과는 `data/exports/`에 저장하며 Git에는 API 키나 로그인 정보가 들어가지 않는다.
