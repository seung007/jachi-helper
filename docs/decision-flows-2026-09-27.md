# 상황별 준비 1차 구현

> 필요시 읽는 당시 근거/검토 기록이다. 최신 상태는 [현재 작업](current-work.md), 방향·실행 규칙은 [제품 방향](product-vision.md)과 [AGENTS](../AGENTS.md)를 따른다. 아래 제안·실험 문턱·당시 승인·집계는 현재 명령이나 새 작업의 승인으로 재사용하지 않는다.

## 범위와 근거

- 기존 준비물 카탈로그를 유지하고 입주청소·이불 선택 흐름만 추가한다.
- 출발점: `docs/chat-product-opportunities-2026-09-26.md`의 사례 분석. 대화에서 관찰한 고민은 기능 후보의 근거이지, 전체 자취생의 발생률이나 전환 효과를 입증한 자료가 아니다.
- 원문, 참여자 정보, 대화 인용을 공개 페이지에 포함하지 않는다.
- 이번 규칙은 편집자가 정한 준비 순서다. 비용, 인기, 제품 성능이나 업체 작업 가능 여부를 보장하지 않는다.
- 기존 SEO 제목과 검색 실험은 변경하지 않는다. 개인 조건 화면 `/decision`은 noindex다.

## 규칙 v1

| 상황 | 조건 | 우선 제시 |
|---|---|---|
| 청소 | 누수 흔적·반복 오염, 또는 모르는 조건 있음 | 방 상태 확인 |
| 청소 | 위 조건 없이 업체 선호, 넓은 공간, 찌든 때 중 하나 | 동일 범위 견적 문의 |
| 청소 | 작은 공간 + 일반 오염 + 직접 할 여건 | 직접 할 구역 정리 |
| 이불 | 계속 쓸 이불 보유 | 보유품 반영, 추가 구매 링크 없음 |
| 이불 | 보유 여부·크기·관리 방식 중 미확인 | 확인할 일 저장, 구매 링크 없음 |
| 이불 | 새로 필요 + 크기·관리 방식 확인 | 선택한 크기 그룹과 관리 방식으로 검색 |

청소의 우선 제시는 강제가 아니다. 사용자가 직접 청소·견적 문의·조건 확인 중 다른 행동을 저장할 수 있다. '커버 없이 세탁'을 특정 제품의 기계세탁 가능 판정으로 바꾸지 않는다.

확인한 공식 참고:
- [미소 입주청소 안내](https://www.miso.kr/deepcleaning-training): 작업 범위·현장 조건을 확인하는 연결처. 수치 견적을 복제하지 않음.
- [IKEA 규격·관리 표시 예시](https://www.ikea.com/kr/ko/p/piltandvinge-duvet-cover-and-pillowcase-grey-70579101/): 개별 상품마다 치수·관리 표시를 확인해야 한다는 예시이며 해당 상품을 추천하지 않음.

## 연결과 저장

- 홈의 상황 링크, '입주청소/이불' 상황 검색, 생활 서비스, 이불 상세에서 진입한다.
- 작성 중 조건도 저장한다. 결과 확인, 다음 행동 저장, 실제 진행 상태는 별개다.
- `jachi-helper:v1.decisionJourneys` 아래 상황별 버전·조건·예산 메모·행동·진행 상태·만료 시각을 저장한다.
- 각 상황의 마지막 수정부터 30일. 단순 재방문은 만료 시각을 연장하지 않는다.
- 홈과 준비표에서 이어보기, 다른 탭 변경 반영, 열린 화면에서 만료 처리를 지원한다.
- 상황 초기화는 준비표 보유품을 지우지 않는다. 사용자가 보유 또는 준비 완료를 명시한 이불만 기존 준비표 보유품에 반영한다.
- 저장소 사용 불가 시 현재 화면의 메모리로만 유지하고 저장 실패를 알린다.
- 예산은 메모다. 실제 상품 가격 필터로 오인시키지 않는다.
- 외부 사이트 이동만 제공한다. 문의문 자동 전송, 예약, 결제 완료 추정은 하지 않는다.

## 계측 계약

| 이벤트 | 의미 |
|---|---|
| decision_open | 상황 진입 링크 클릭 |
| decision_start | 새 시도에서 첫 조건 변경 또는 건너뛰기 |
| decision_answer | 변경한 질문 이름만 기록; 답변·예산 원문 제외 |
| decision_result_view | 조건 결과 처음 확인 |
| decision_complete | 다음 행동을 명시적으로 저장; 시도별 1회 |
| decision_action_change | 완료한 시도의 다음 행동 변경 |
| decision_outcome | 사용자가 직접 표시한 진행 상태 |
| decision_reset | 해당 상황 초기화 |
| store_click | 기존 판매처 이동 이벤트, placement=decision |
| service_outbound | 기존 업체 이동 이벤트 |

시도 ID와 scenario로 start→complete를 연결한다. 홈 전체의 판매처 클릭/결과 조회를 섞어서 완료율로 부르지 않는다. 새로고침·같은 조건 재확인은 완료 이벤트를 추가하지 않는다. 새 조건 수정은 새 시도이며 과거 완료와 분리한다.

## 검증과 남은 범위

- `npm run check`: 기존 SEO·39개 품목 검사와 순수 분기/예산/만료/입력 검증.
- `npm run verify:decision`: 브라우저 조건 입력, 저장·복원·만료·다른 탭·저장 차단 및 360/390/768/1024/1440px 화면 검사.
- 브라우저 검사는 외부 분석 요청을 차단한다. GA4 수집·보고서 반영은 프로덕션 승인 배포 뒤 별도 확인해야 한다.
- 실제 전환 개선 효과, 업체 문의 접수, 구매 성사, 상품 가격 연동은 아직 검증되지 않았다.
- 커밋·푸시·배포는 사용자 승인 전 실행하지 않는다.

## 로컬 검증 완료 (2026-09-28)

- `npm run check` 통과: SEO, 39개 품목 안내, Node 테스트 10개.
- `npm run verify:decision` 통과: 조건 분기, 저장·새로고침 복원, 중복 완료 방지, 기존 준비표와 저장 공존, 다른 탭 반영, 저장 차단, 잘못된 경로 처리.
- 브라우저 시계를 두 번에 걸쳐 총 32일 앞당겨 열린 화면에서 만료 후 입력 화면으로 돌아가는 것을 확인했다. 실제 30일을 기다린 관측은 아니다.
- 청소 입력·결과를 360/390/768/1024/1440px에서, 홈과 이불 입력을 360/768/1440px에서 검사했다. 이불 결과는 360/1440px에서 확인했다. 가로 넘침·검사 대상 텍스트 잘림·페이지 JavaScript 오류 없음.
- 모바일 캡처를 직접 확인하고 공통 입력 스타일로 커진 라디오 높이와 판매처 버튼의 11px 자식 글씨를 수정했다.
- 기존 카탈로그 6→39개 확장, 세제 8개 및 운동 조건, 생활 서비스 외부 링크 4개를 확인했다. 테스트는 링크 개수가 아니라 고유 품목 ID로 상품 수를 센다.
- 캡처와 결과: `data/exports/decision-verification/`. 비공개 출력이며 커밋 대상이 아니다.
- 로컬 미리보기: `http://localhost:4175/`. 운영 사이트 반영과 GA4 실수집은 미실행.
