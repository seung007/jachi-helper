# 대화 분석 재검토와 제품 반영

> 필요시 읽는 당시 근거/검토 기록이다. 최신 상태는 [현재 작업](current-work.md), 방향·실행 규칙은 [제품 방향](product-vision.md)과 [AGENTS](../AGENTS.md)를 따른다. 아래 제안·실험 문턱·당시 승인·집계는 현재 명령이나 새 작업의 승인으로 재사용하지 않는다.

## 판단 기준

- 요청: 대화 분석을 다시 검토하고 설계 문서에 맞는 기능을 실제 사이트에 추가한다.
- 기준 문서: [제품 비전](product-vision.md), [수정된 대화 분석](chat-product-opportunities-2026-09-26.md), [상황별 준비 1차](decision-flows-2026-09-27.md).
- 현재 단계는 안내다. 사용자 조건으로 다음 행동을 정리하고 공식 연결처로 이동하되, 신청·예약이 사이트 안에서 완료된다고 약속하지 않는다.
- 채팅은 문제와 누락 조건을 발견하는 질적 근거다. 표본의 빈도를 전체 수요·인기·구매 의사로 일반화하지 않는다.
- 이미 적용한 57종 준비물, 입주청소·이불 흐름은 유지한다. 같은 목록을 다시 추가하는 대신 빠져 있던 문의 준비와 후속 확인을 보완한다.

## 원문 확인과 반영

원문은 비공개 `data/exports/chat-research-8f5d54b60924/messages.private.jsonl`에서 구조화된 ID로 확인했다. 대화 원문, 닉네임, 지역 정보는 이 문서나 공개 화면에 복사하지 않았다.

| 확인 근거 | 관찰 | 이번 반영 |
|---|---|---|
| m050113~m050116, 원본 52410~52413행 | 이사 비용 질문에 거리·짐 양 등 조건이 빠져 있고 후속 대화에서 조건 필요성이 등장 | 짐 종류, 이동 범위, 필요한 도움 3문항과 업체에 전달할 문의문 |
| m125599, 원본 132460~132464행 | 서비스 이용 이후에도 문제가 남는 사례 | 청소·이사 흐름에 사용자가 직접 선택하는 `다시 확인 필요` 상태와 후속 확인 항목 |

두 번째 사례가 청소·이사 모두의 효과를 입증하는 것은 아니다. 서비스 클릭과 해결을 분리해야 한다는 설계상의 추론으로 적용했다. 사례의 원인을 진단하거나 창호 교체·약품 사용을 권하지 않는다.

## 추가한 흐름

1. 홈, 상황 검색(용달·원룸 이사·이사 견적 등), 생활 서비스에서 이사 문의로 진입한다.
2. 확정하지 않은 조건은 `미정`으로 남긴다. 미정이 있으면 조건 확인을 먼저 제안한다.
3. 운송만 필요한지, 상하차·포장 도움이 필요한지 선택에 맞는 문의문을 만든다. 날짜·층수·엘리베이터·주차·큰 짐 치수 등 아직 받지 않은 정보는 추가 확인 대상으로 분리한다.
4. 공식 업체 사이트로 이동한다. 문의문은 자동 전달되지 않으며 실제 견적·신청은 업체에서 진행한다.
5. 청소·이사에서 `진행 전 / 문의 후 확인 중 / 다시 확인 필요 / 완료`를 직접 표시한다. 문의 상태는 견적 문의 행동을 저장한 경우에만 제공한다.
6. 후속 확인 상태는 홈과 내 준비표에서 다시 이어진다. 저장은 마지막 수정부터 30일, 기존 준비물 상태와 별도 유지한다.

## 외부 근거의 범위

- [짐싸 공식 홈페이지](https://www.zimssa.com/): 2026-09-28 확인. 이사·운송의 공식 연결처를 확인한 용도다. 개별 이용자의 가격, 차량 크기, 서비스 가능 지역·날짜를 검증한 것이 아니다.
- 사용자가 실제로 받은 견적, 상품 가격·재고, 인기순위 데이터는 없다. 해당 수치와 순위는 생성하지 않는다.
- 원문의 비용 답변을 현재 시세나 견적 기준으로 옮기지 않는다.

## 이번에 보류한 항목

- 임대인 연락·계약 책임: 연락문 준비 후보는 남기되 법적 책임·비용 부담 판단으로 확장하지 않는다.
- 세탁·오염 제거법: 제품별 관리 표시와 제조사 근거 없이 원문 조언을 처방으로 옮기지 않는다.
- 예약·자동 견적·최저가: 파트너 연동과 공식 데이터가 없으므로 안내 범위를 유지한다.
- 재방문·전환 상승은 아직 측정되지 않았다. 이번 변경의 효과라고 주장하지 않는다.

## 검증 범위

- 단위 검사: 이사 36개 조합, 미정 우선 처리, 잘못된 상태 정규화, 기존 저장 호환, 개인정보·가상 가격 없는 문의문.
- 브라우저 검사: 홈·검색·서비스 진입, 조건 저장, 외부 클릭과 완료 구분, 후속 상태 새로고침·재방문, 360/390/768/1024/1440px 레이아웃.
- 기존 청소·이불·준비표·57종 카탈로그 회귀 검사 포함.
- 로컬 구현이며 커밋·푸시·배포는 승인 전 수행하지 않는다.

검증 결과: `npm run check` 통과(SEO, 57종 품목 검사, 12개 테스트). `npm run verify:decision` 통과(9개 검증 묶음, 브라우저 오류 0개). 위 다섯 화면 폭에서 이사 입력·후속 확인 화면의 가로 넘침과 글자 잘림을 검사했다. 캡처와 결과는 비공개 `data/exports/decision-verification/`에 둔다.

## 후속 확장: 수납 선택과 결과 피드백

사용자가 완료 항목을 정리하고 분석에서 남은 일을 계속 구현하도록 요청해 추가했다. 위 이사 문의 구현 이후의 변경이다.

### 근거와 해석

- 기존 분석의 다음 우선순위는 품목별 조건 확장과 실제 도움 여부 확인이다. 제품 비전의 생활 맞춤 선택 범위를 따른다.
- 원문 m096707(101718행), m096709(101720~101721행), m096711(101723행)을 다시 확인했다. 꾸미기에서 실제 짐·수납으로 관심이 바뀌는 사례다. 같은 구간의 무관한 광고 링크는 근거에서 제외했다.
- m150451~m150454(159591~159602행)는 공간·예산에 비해 과도한 제품 제안에 대한 불만이다. 수납제품 특정 브랜드나 효능의 근거가 아니라 구매 이전의 조건 확인이 필요하다는 보조 근거다.
- 위 관찰에서 보유품·공간·목적을 묻는 3문항을 설계했다. 질문과 분기 규칙은 제품 설계상의 추론이며 검증된 수요 순위나 제품 적합성 판정이 아니다.

### 구현 범위

- 홈, 수납 관련 상황 검색, 수납 박스 상세에서 `/decision?scenario=storage`로 들어간다.
- 보유품을 쓰겠다면 이후 문항을 생략하고 정리할 일을 제시한다. 가진 것이 미정이면 확인부터 안내한다.
- 새 구매는 놓을 공간과 정리 목적을 확인한 경우에만 제품군 검색으로 연결한다. 실측 값과 제품 치수를 대조한 자동 크기 추천은 아니다.
- 옷·침구 / 생활 소모품 / 작은 잡동사니에 따라 검색어가 다르다. 공간 미정·공간 없음에는 구매 링크를 만들지 않는다.
- 선반을 재사용했다고 수납 박스를 보유품으로 자동 체크하지 않는다. 진행 상태는 해당 상황에만 남긴다.
- 모든 상황 결과에 선택적 도움 여부와 부족한 이유를 추가했다. 선택은 상황별 30일 저장 정책을 따르고 조건을 바꾸면 이전 결과의 의견을 초기화한다.
- 피드백 선택은 `decision_feedback`, 이유 변경은 `decision_feedback_reason`으로 구분한다. 알려진 항목 코드와 결과 코드만 전송하며 답변 원문·예산·문의문은 보내지 않는다. 새로고침만으로 재발화하지 않는다.
- 피드백 이벤트는 변경 기록이다. 단순 이벤트 수를 사용자 수나 도움 비율로 계산하지 말고 같은 `attempt_id`의 마지막 선택을 기준으로 분석해야 한다. 프로덕션 GA4 수집 여부와 효과는 아직 미확인이다.

### 이후 남은 일

후속 검증: `npm run check` 14개 테스트 및 SEO·57종 품목 검사 통과. `npm run verify:decision` 10개 검증 묶음, 브라우저 오류 0개. 수납 결과·피드백 화면을 360/390/768/1024/1440px에서 검사했으며 모바일·PC 캡처를 직접 확인했다. 커밋·푸시·배포와 프로덕션 계측 확인은 수행하지 않았다.

1. 배포 승인 후 실제 사용자의 도움 여부·부족한 조건을 확인하고 질문을 다듬기.
2. 임대인·관리자에게 보내는 중립적인 문의문과 방문 일정 조율. 비용 부담·계약 책임 판정은 제외한 별도 범위로 구현하기.
3. 세탁·보유 제품 관리 안내는 제조사 표시와 공식 근거 확보 후 확장하기.
4. 실시간 가격·인기순·예약 자동 전송은 공식 데이터와 연동 준비 뒤 진행하기.
