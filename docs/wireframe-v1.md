# 와이어프레임 v1

2026-10-19. **v1은 사용자가 UI/UX를 부적합하다고 평가한 이전 시안이다. 제품 적용하지 않는다.** v2 독립 시안 제작 상태는 다음 절을 따르며, 제품 이식은 승인 전이다. 기존 홈·상품·생활 서비스 코드는 변경하지 않는다.

## 최신 실행: 상품 흐름 v2

사용자의 후속 `만들어` 지시로 아래 재설계의 **독립 상품 흐름 시안 제작**을 진행했다. 설계 전체의 운영 적용 승인을 뜻하지 않는다.

- [v2 직접 조작](wireframe-v2/index.html) · [세 장의 화면 흐름](wireframe-v2/board.html) · [공유용 개요 이미지](wireframe-v2/overview.png)
- 홈은 검색과 사진 품목 탐색, 전체 분류는 대분류/품목 패널이다. 특정 냄비 모델 여섯 개를 전체 홈으로 쓰지 않는다. 검색과 분류로 같은 품목에 도달한다.
- 품목 후보에서 정확한 이름·옵션·핵심 특징과 구매 버튼을 기본 표시한다. 목록의 저장/비교 체크박스·준비표 유도는 제거했다. 상품명이나 사진을 누르면 상세 속성이 열린다.
- 차이 보기는 누른 상품이 기준인 패널로 바로 열린다. 비교함은 없고 같은 품목의 다른 후보를 교체할 수 있다. 기본은 차이만 표시하며 미확인 값은 같다고 숨기지 않는다. 초기 대조 후보는 확인된 용량/길이가 다른 첫 후보를 우선할 뿐 추천 순위/우열이 아니다.
- 조건 패널 적용/해제, 이름순, 번호 페이지, 검색어/조건/스크롤 복귀, Escape 및 초점 복귀를 연결했다. 모바일에서는 불필요한 상위 경로 문구를 숨기고 주요 구매/비교 행동에 44px 높이를 사용했다. PC에도 동일 흐름을 유지한다.
- 정확한 쿠팡 상품 링크만 `쿠팡 상품 보기`다. 그 외는 원판매처의 해당 상품으로 간다. 검색 링크를 동일 상품 구매로 표시하지 않았다. 가격·평점·후기·효능을 새로 만들지 않았다.
- 기존 v1 공개 자료 210품목/226대표·집중 후보를 그대로 재사용했다. 냄비/수건/일반 세탁세제 외의 품목은 대표 하나이므로 전 품목 비교군 수집 완료가 아니다. 수집용 기술 키는 사용자 화면에서 제외하고 알려진 필드명을 한글 표시했다. 원본 필드·출처는 삭제하지 않았다.
- 로컬 `/assets/` 사진은 시안 위치에서 안전하게 해석한다. 외부 이미지가 실패하면 해당 사진 자리의 크기를 유지하는 아이콘으로 표시하고 무관한 품목 사진을 넣지 않는다. Pretendard 원격 스타일과 시스템 대체 글꼴, 기존 Lucide 패키지의 아이콘/ISC 라이선스를 사용한다.
- 우리동네·생활 서비스·기존 제품 HTML/JS·SEO·수집 데이터는 수정하지 않았다. 시안은 `docs/`에 있어 기존 Vercel 제외 경계 안에 있다. 제3자 HTML/스크립트를 제품으로 복사 배포한 것이 아니라, 앞서 수집한 구조/치수 관찰에 맞춰 별도 구현했다.

2026-10-19 검사: 320/390/768/1440px의 여섯 상태와 최장 이름을 포함한 25레이아웃, 검색·분류 일치/210품목 접근/즉시 비교·교체/조건/구매 URL/복귀/사진 실패 등 **73항목 통과**. 개요의 관찰 사진 19개 로드, 관찰 영역 실패 자리 0개. 이는 전체 외부 사진의 현재 유효성이나 실제 고객 만족을 입증하지 않는다. 기존 `npm run check` 171개·SEO·66안내 통과. 검사 출력은 `output/playwright/wireframe-v2/report.json`이다.

재현: `node scripts/build-wireframe-v2.mjs`는 시안용 아이콘만 생성한다. `node scripts/verify-wireframe-v2.mjs`는 설치된 Edge/Playwright로 검사한다. 서버 없이 v2 `index.html`을 열 수 있다. 실제 사용자 과업/시각 선호 평가와 제품 이식은 다음 검토 대상이다.

## 재설계: 실제 HTML 구조와 고객 과업부터

### v1에서 잘못 잡은 것

1. 첫 화면을 상품 탐색이 아니라 검색창과 분류 선택창을 채우는 화면으로 만들었다. 품목을 모르는 사람과 이미 수건을 찾으러 온 사람을 같은 입력 순서로 묶었다.
2. 전 품목 진입 화면의 첫 여섯 후보를 냄비로 채웠다. 데이터 배열 순서가 서비스의 첫인상을 결정하게 했고, 먹거리·다른 생활용품을 찾는 진입점은 약했다.
3. 카드마다 저장·비교 체크·제품 정보가 반복됐다. 제품 특징과 구매라는 핵심 행동보다 보조 행동의 비중이 컸다.
4. 비교하려면 체크 → 비교 목록 → 별도 화면 → 제품 교체를 거친다. 단순히 후보의 다른 점을 읽으려는 사람에게 선택 상태 관리까지 요구했다.
5. 우리동네에서 지역·업종 입력 네 칸과 자리 표시자 설명부터 보여 줬다. 입력은 정돈됐지만 실제 결과를 빨리 이해하는 데 도움이 된다는 근거는 없었다.
6. 59개 기계 검사는 동작/기하 검사다. 배치가 좋다거나 탐색이 쉽다는 판정으로 확장할 수 없고, 사용자의 부정 평가를 그 검사로 반박하지 않는다.

### 다음 화면 제작의 범위

이 턴에는 새 제품 코드나 v2 화면을 성급히 추가하지 않는다. 이번 수정안 검토 후 **홈 → 품목 결과 → 차이 보기**를 연결한 대표 상품 흐름을 먼저 만든다. 색만 바꾸는 안이나 네 화면 전체를 다시 만드는 방식은 쓰지 않는다. 지역·서비스 흐름은 위 설계에 맞춰 이어서 검토한다. 이는 전체 품목/서울/서비스 목표를 줄이는 것이 아니라 반복 제작을 줄이기 위한 검토 순서다.

다음 시안의 종료 기준은 화면 범위 검사에 더해, 품목 검색과 분류 경로가 같은 결과로 모이는지, 카드에서 바로 구매할 수 있는지, 비교 목록을 만들지 않고 차이를 읽을 수 있는지, 복귀 후 조건이 보존되는지를 직접 수행하는 것이다. 실제 고객에게 쉽다/예쁘다는 결론은 별도 과업 관찰과 선호 평가 전에는 내리지 않는다.

## 1. 화면의 역할

상품을 찾고 차이를 판단해 판매처로 가는 것이 첫 경로다. 준비표 작성·지역 입력·로그인을 통과해야 상품을 보는 구조는 쓰지 않는다.

주 메뉴는 **상품 / 우리동네 / 생활 앱** 세 개를 제안한다. 저장은 헤더의 보조 아이콘이다. 이는 새 제안이지 확정된 과거 합의가 아니다. 메뉴 수 자체가 성과를 보장하지 않으며 실제 과업 관찰 뒤 바꿀 수 있다.

```text
상품                            우리동네                 생활 앱
검색·카테고리·품목              구 → 동                  필요한 일
```

시안은 6행 단위로 넘긴다. 이것은 구현 상한이 아니라 첫 검토값이다. 실제 사진 품질·읽기 속도를 보고 바꾼다. PC는 가로 공간에 맞춰 2~3열, 모바일은 가로 스크롤 없는 한 열이다.

**상품 데이터 경계:** 기존 210개 품목을 유지하고 냄비·수건·세제의 여러 모델을 배치했다. 그 외 품목은 대표 모델 하나만 넣어 탐색 구조를 검토한다. 전체 상품 수집·다양한 브랜드 확보·전 품목 최소 5개 비교군의 완료를 뜻하지 않는다. 이 범위 축소는 시안 표시량이지 원래 수집 목표 변경이 아니다.

현재 사진과 모델은 주로 기존 판매처 자료다. 동일 쿠팡 상품 URL이 확인된 경우만 `쿠팡 상품 보기`, 그 외는 판매처 이름을 상품명 위에 표시하고 `판매처 보기`로 원상품에 연결한다. 쿠팡 API로 동일 모델·옵션을 연결한 뒤 그 버튼을 쿠팡으로 바꾸는 것이 목표이며, 검색 결과를 동일 상품 구매로 위장하지 않는다. 품목 검색을 메인 판매처로 오인시키지 않는 설계다. 목록의 장문 소재 정보는 원문 첫 절로 줄이고 전체 값은 제품 정보에 보존한다.

가격·평점·후기는 검증 자료가 없어 만들지 않았다. 추후 연결하면 상품명 아래 **평점 + 후기 수 + 출처**, 주요 특징 아래 **정확한 옵션의 가격·배송 조건**, 펼침에 **긍정/불편의 구체 내용과 근거**를 둔다. 출처 없는 별점, 후기를 읽지 않고 쓴 후기 요약, 근거 없는 인기순은 넣지 않는다. 시안의 가격/평점 정렬은 비활성이며 운영에서는 연결되기 전 숨긴다.

## 3. 차이 비교

제품 선택 → 차이 비교 → 같은 기준을 나란히 읽기 → 제품 교체 또는 판매처 이동.

| 구성 | 설계와 이유 |
|---|---|
| 상단 | 제품별 선택창·사진·이름·판매처 버튼. 구매 행동을 표 맨 아래로 내리지 않음 |
| 2열 | 좁은 화면에서 가로 스크롤 없이 같은 항목의 두 값을 맞춰 읽음. 전체 후보를 두 개로 줄이는 뜻이 아님 |
| 후보 교체 | 해당 품목의 시안 후보 전부를 선택 가능. 선택이 여러 개여도 한 번에 두 상품을 보여 주고 드롭다운으로 교체 |
| 비교표 | 용량, 인덕션, 가스, 소재 등 확인된 원래 필드. 다른 품목은 그 품목의 실제 필드 사용 |

장문 상품명 때문에 버튼 위치가 크게 어긋나지 않도록 두 열의 높이를 맞춘다. 모바일에서는 상단을 고정해 표를 가리지 않고, PC에서만 비교 헤더를 고정한다. 실제 손가락 탐색과 여러 후보를 번갈아 보는 비용은 별도 사용자 과업으로 검증한다.

## 4. 우리동네

**지역 2칸 → 업종 2칸 → 검색창 → 장소 목록** 한 묶음이다. 앱 목적 필터·서울 전체 버튼·지역 설정 버튼이 여러 곳에 중복되지 않게 한다.

| 구성 | 설계와 이유 |
|---|---|
| 구·동 | 서울 25구, 선택 구의 법정동만 두 번째 선택창에 표시. 구를 바꾸면 동 초기화 |
| 업종·세부 업종 | 생활권의 물리적 장소로 분류. 장소와 설치 앱을 같은 목록에서 섞지 않음 |

| 목록 첫 항목 | 업종·상호·무엇을 하는 곳인지·주소·위치 버튼을 한 항목에 배치 |

현재 시안 장소는 **명시적인 자리 표시자 12개**다. 구·동 선택은 기존 마스터를 재사용했지만 모든 업소의 영업/설명/별점이 확인된 것처럼 채우지 않았다. 위치 버튼은 연결 구조를 보여 주는 도식이며 실제 카카오 업체로 가지 않는다. 공개 업체 데이터 연결과 설명·평가 자료 확보는 설계 승인 후 별도 구현/검증이다. 원자료 기준일 6월을 10월로 바꾸지 않는다.

## 5. 생활 앱

검색 + 필요한 일 선택 → 이름·한 줄 설명 → 서비스 소개/공식 안내/설치.

앱 이름만 보고 무엇인지 추측하지 않게 기존 설명을 기본 표시한다. 플랫폼 이름을 눌러야만 설명을 볼 수 있는 구조는 쓰지 않는다. 웹 소개·기관 안내는 주 행동, 실제 URL이 있는 App Store·Google Play만 보조 행동으로 노출한다. 앱 아이콘 권리를 확인하기 전에는 글자 타일을 쓰며 임의 로고를 만들지 않는다.

기존 기본 노출 대상 73개를 사용했다. 73개의 설치/예약/현재 운영을 이번에 새로 검증한 것이 아니다. 조사 원장에 남은 링크 확인 대기는 유지한다. 빼기의 강북구 안내 URL은 `강북구 배출 안내`라고 표시해 서비스 홈페이지와 구분했다. 이는 시안만의 문구 수정이며 제품 자료는 그대로다.

## 6. 시각 규격과 근거

모바일 좌우 16px, 본문 14~15px, 상품명 15px, 페이지 제목 21px, 기본 행간 1.5~1.65를 검토값으로 잡았다. 주요 조작은 44px, 사진은 정사각형 `contain`, 긴 이름은 줄바꿈, 메뉴 문구는 세 화면에서 동일하다. 큰 히어로·색상 장식·중첩 카드 대신 흰 바탕과 구분선 중심으로 정보 우선순위를 확인한다. 이것은 미적 선호가 증명된 최종 디자인이 아니다.

2026-10-19까지의 확장 조사에서 **사용할 패턴만** 가져왔다. 아래 사이트로 후보를 제한하는 규칙은 없다. 성공한 회사라는 사실과 특정 UI의 효과를 동일시하지 않는다.

| 참고 관찰 / 자료 | 채택 패턴 | 채택하지 않는 주장 |
|---|---|---|
| 쿠팡·오늘의집·IKEA의 상품 정보 배치, Details 상세의 사진/모델/CTA 동시 노출 | 정확한 제품 사진과 특징 가까이에 판매처 행동 | 우리 자료에 없는 쿠팡 순위·실시간 가격·원판매처 후기 복제 |

브랜드별 관찰 범위·원본 캡처·성능/만족 분리 근거는 기존 [조사 문서](ui-benchmark-2026-10-10.md)에 있다. 이번에는 새 스크랩 수량을 늘리거나 새 사용자 조사 결과를 만든 것이 아니다.

## 7. 종료 기준과 다음 승인

이번 종료는 시안의 **동작·화면 범위·자료 정직성** 확인이다. 예쁘다/쉽다/오래 머문다는 결론은 내리지 않는다.

- 320·390·768·1440px에서 가로 잘림, 글자·버튼 겹침, 주 메뉴와 페이지 번호 충돌 확인.
- 상품 검색/빈 결과/번호 이동/조건 초기화/비교·교체/차이만 보기/저장·복귀/사진 실패 검사.
- 서울 25구·종속 동 초기화·업종·세부 업종·검색·위치 도식·Escape 복귀 검사.
- 실제 판매처 URL과 표시 문구 대조. 가격·별점·후기·장소가 생성되지 않았는지 확인.
- 시안은 메모리 저장이므로 새로고침 후 저장이 초기화된다. 운영의 영속 저장 완료로 보고하지 않는다.

사용자 검토 과업은 '인덕션 3L 냄비를 골라 판매처로 가기', '수건 두 모델의 다른 점 찾기', '선택 동네의 빨래방을 찾고 위치 행동 고르기', '수거 세탁 서비스 설명을 읽고 적절한 소개/설치 링크 고르기'다. 멈춘 곳·되돌아간 곳·잘못 누른 곳을 먼저 기록하고, 별도로 시각 선호를 묻는다. 수행 시간이나 성공률 목표를 임의로 통과 처리하지 않는다.

시안 검토 후 메뉴, 상품 행의 정보량, 비교 방식, 지역 필터를 승인/수정한다. 이후 제품 파일 변경 범위와 자료 연결 조건을 묶어 로컬 구현한다. 현재 승인으로 제품 UI까지 옮기지 않는다.

## 재현

`node scripts/build-wireframe-v1.mjs`로 기존 공개 자료에서 시안 데이터를 생성한다. `node scripts/verify-wireframe-v1.mjs`는 Edge/Playwright로 시안 동작과 화면을 검사한다. 서버 없이 `board.html` 또는 `index.html`을 열 수 있다. 검사 출력은 `output/playwright/wireframe-v1/`, 공유용 개요 이미지는 `wireframe-v1/overview.png`다.

2026-10-19 실행: 320/390/768/1440px의 네 화면 16조합과 조작을 포함한 59항목 통과. 개요 첫 화면에서 관찰한 사진 4개 로드, 사진 실패 별도 검사 통과. 기존 제품 회귀 171개·SEO·66안내 통과. 전체 외부 사진·업소/앱 이용·실제 사용자 선호 검증은 이번 결과에 포함하지 않는다.
