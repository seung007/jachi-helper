# 생활조건형 상품 비교 및 서비스 연결 방향 검증

- 작성일: 2026-09-09
- 범위: 자취도우미 기획 문서, 현재 제품 구조, 채찍단 공개 화면, 공식 데이터/API 정책, 소비자 시험 자료
- 판단 방식: Council 5개 관점(제품, 실증, 반대, 시스템, 운영 책임) + 근거 재검증

## 결론

제안의 핵심 전략에 동의한다. 이미 잘 작동하는 서비스의 탐색·비교 패턴을 먼저 가져와 출시 시간을 줄이고, 우리 데이터는 출시 허가가 아니라 출시 후 우선순위와 정교화를 판단하는 데 사용한다.

- 맞는 부분: 생활 조건을 세분화해 제품 선택 이유를 설명하고, 실제 상품 이미지·가격·구매 링크를 한 화면에서 비교하게 만드는 방향
- 바로 적용할 부분: 39개 전 품목에 모바일 검색·카테고리·조건 필터·이미지 카드·상세 화면·저장 구조를 적용
- 깊게 채울 시작점: **세탁 세제 1개 품목군**에서 `실내건조`, `운동복`, `향·성분 민감`, `세탁기 종류`, `1회 사용비`와 실제 상품 데이터를 먼저 완성
- 수정할 부분: 공급 근거 없이 전 품목에 실시간 `인기순`, `최저가순`을 붙이는 방식
- 서비스 연결: 별도 `생활 서비스` 영역에 이사·입주청소·인터넷·폐기 탐색 구조를 먼저 만들고, 실제 예약·제휴 연결은 공급 조건이 갖춰지는 순서대로 추가

현재 제품은 상품 데이터 플랫폼보다 `내 조건을 한 번 입력하면 준비·구매·생활 서비스의 다음 행동을 정리해 주는 시스템`으로 정의하는 편이 강하다. 상품 비교와 외부 서비스는 이 시스템 안의 실행 수단이다.

## Council 판정

판정 점수는 7점이다. 가역성은 높지만 잘못된 가격·인기 표시의 신뢰 손실과, 경쟁 화면을 그대로 따라가고 싶은 확증 편향 위험이 있어 5개 관점으로 검토했다.

| 관점 | 판정 |
|---|---|
| 제품 | 조건별 추천은 사용자가 `무엇을 사야 하는가`보다 `왜 이 제품이 내 상황에 맞는가`를 결정하게 한다. 진행 가치가 있다. |
| 실증 | 채찍단 등 외부 사례는 탐색·비교 구조를 지금 적용할 충분한 벤치마크다. 현재 GA 표본은 출시를 막는 기준이 아니라 출시 후 카드·분류·후속 기능의 우선순위를 조정하는 자료다. |
| 반대 | 공식 공급권 없이 전 품목 가격 사업을 약속하면 품절·옵션·배송비·이미지 권리 문제로 오정보 제품이 된다. |
| 시스템 | 장기 자산은 가격 스냅샷 수가 아니라 `생활조건 → 결정 → 구매 → 후속행동` 데이터다. |
| 운영 책임 | 낡은 가격과 과장된 순위의 비용은 사용자가 부담한다. 외부 서비스 사고·계약 책임도 화면에서 분리해 알려야 한다. |

수정된 실행 순서는 `전체 탐색 골격 출시 + 한 품목의 깊은 비교 → 실제 행동으로 우선순위 조정 → 공급원과 서비스 연결 확대`다. 전 품목 UI를 만드는 일과 전 품목 실시간 가격망을 운영하는 일은 분리한다.

## 채찍단에서 가져올 것과 버릴 것

채찍단의 핵심은 카드 모양이 아니라 **하나의 비교 가능한 단위와 가격 맥락**이다. 공개 상품 상세에는 실제 상품 이미지, 현재 가격, 단백질 단위 가격, 가격 범위·이력, 찜·알림, 구매 링크, 제휴 고지가 한 흐름에 있다.

### 가져올 40·40·20

| 비중 | 가져올 대상 | 자취도우미 적용 |
|---|---|---|
| 40% | 모바일 정보 구조 | 즉시 검색, 상단 카테고리, 정렬, 하단 내비게이션, 짧은 카드에서 상세로 이동 |
| 40% | 의사결정 구조 | 표준 단위 비용, 비교 근거, 관찰 시각, 출처, 가격·재고 변경 가능성, 저장·알림 |
| 20% | 자취도우미 고유 구조 | 첫날/7일/나중, 생활조건 재사용, 보유품 제외, 서비스 후속행동 |

### 그대로 가져오지 않을 것

- 판매처 HTML을 광범위하게 크롤링해 가격·이미지를 재게시하는 방식
- 동일 상품·옵션·수량·배송 조건이 아닌 값을 `최저가`로 부르는 방식
- 검색량, 리뷰 수, 광고 노출을 실제 구매 인기로 바꾸어 말하는 방식
- 상품 카탈로그와 이사·청소·폐기 서비스를 홈 한 화면에 모두 나열하는 방식
- 채찍단 UI가 성장을 만들었다고 단정하는 것. 공개 화면은 구현 사례일 뿐 인과 증거가 아니다.

채찍단의 초기부터 현재까지의 유입·전환·잔존 성장 수치는 공개 자료에서 확인되지 않았다. 따라서 성장 서사를 추정해 베끼지 않고, 확인 가능한 화면 구조만 참고한다.

## 권장 제품 구조

1. `홈`: 지금 해야 할 일과 내 조건에 맞는 빠른 미리보기
2. `준비물`: 39개 품목의 단계·조건 분류와 체크리스트
3. `비교`: 검증된 데이터가 있는 소수 품목만 실제 상품 단위로 비교
4. `생활 서비스`: 이사·입주청소·인터넷·폐기 등 실행 서비스의 비교 기준과 외부 연결
5. `내 계획`: 저장한 결정, 완료 여부, 일정, 알림

39개 품목은 버리지 않는다. 다만 모두를 실제 상품 비교 대상으로 취급하지 않고, 먼저 체크리스트·검색 수요를 관찰하는 `품목 지도`로 유지한다.

## 사용자 유형 분류

연령이나 성별보다 실제 결정에 영향을 주는 조건을 쓴다.

| 축 | 예시 |
|---|---|
| 시점·긴급도 | 입주 첫날, 7일 안, 실측 뒤, 소진 뒤 재구매 |
| 주거 환경 | 옵션 포함 여부, 세탁기 종류, 실내건조/건조기, 수납 크기 |
| 생활 행동 | 요리 빈도, 세탁 빈도, 운동·땀, 반려동물, 재택근무 |
| 선호·제약 | 향 민감, 성분·알레르기 표시, 예산, 공간, 소재 호환 |

예를 들어 `운동을 자주 함` 하나만으로 운동용 세제를 추천하지 않는다. `땀·피지 오염`, `세탁 주기`, `실내건조`, `향 민감`, `표준 사용량`을 함께 보고 제품별 이유를 보여 준다.

## 첫 깊은 비교 품목: 액체 세탁세제

한국소비자원 시험에서는 액체형 세탁세제 8종의 오염별 세척 성능이 달랐고, 1회 세탁비도 56원에서 176원으로 3배 이상 차이가 났다. 이 때문에 세제는 단순 표시 가격보다 `목적별 성능 + 1회 사용비`를 설명하기 좋은 첫 품목이다.

### 첫 세 조건

- 실내건조가 잦아요
- 운동복을 자주 빨아요
- 향·성분에 민감해요

### 최소 데이터 모델

```text
Product
  canonicalId, brand, name, variant, volume, packCount
  imageSource, sourceUrl

Evidence
  washerType, standardDose, costPerWash
  stainPerformance, fragranceInfo, allergenLabel
  evidenceSource, testedAt

Offer
  seller, observedPrice, shippingCost, effectivePrice
  availability, fetchedAt, expiresAt, affiliateDisclosure
```

제품과 판매 제안을 분리해야 같은 세제의 용량·묶음·판매처 가격을 잘못 비교하지 않는다. 실제 상품 이미지는 제조사·판매처 API나 이용 허락이 확인된 소스만 사용한다. 그 전에는 현재의 품목 예시 이미지를 유지하고 실제 제품인 것처럼 보이지 않게 표시한다.

## 정렬 기준

| 이름 | 노출 조건 | 계산 기준 |
|---|---|---|
| 맞춤순 | 즉시 사용 | 필수조건 일치, 근거 완전성, 정보 최신성, 시점 우선순위 |
| 1회 비용순 | 표준 사용량 확인 후 | 배송비를 포함한 실결제 추정액 ÷ 표준 사용 횟수 |
| 관심순 | 내부 표본 확보 후 | 최근 28일 고유 사용자의 저장·상세·구매 클릭. 최소 표본 미달 시 숨김 |
| 가격순 | 같은 SKU·옵션일 때만 | 동일 용량·묶음·상태·배송 조건의 수집된 제안 안에서 비교 |

`인기순`은 당분간 쓰지 않는다. 네이버 Shopping Insight는 키워드 클릭의 상대 추이이며 상품 판매 순위가 아니다. 내부 고유 사용자 표본이 쌓이면 `관심순`으로 시작한다. `최저가`도 전체 시장을 포괄하는 공급원이 없으면 `확인한 판매처 중 낮은 가격`으로 한정한다.

## 데이터 수집 원칙

Scrapling은 다음 범위에만 사용한다.

- 한국소비자원·공공기관의 공개 시험 결과와 리콜·안전 공지
- robots.txt, 이용약관, 저작권과 재이용 범위가 확인된 제조사 공개 정보
- 출처 URL, 수집 시각, 필드별 근거, TTL을 함께 저장하는 내부 검증 자료

다음 용도로는 사용하지 않는다.

- 네이버·쿠팡의 봇 차단이나 본인 확인을 우회
- 로그인·보호 페이지의 상품 데이터 수집
- 허락 없이 판매처 이미지를 복사하거나 핫링크
- 수집 범위를 숨긴 채 `시장 전체 최저가`로 표시

실시간 가격과 실제 상품 이미지는 공식 API, 제휴 피드 또는 판매자 이용 허락이 기준이다. 네이버 쇼핑 검색 API는 2026-07-31 종료되었고 대체 API가 공지되지 않았다. 쿠팡 파트너스 API는 향후 수요가 검증되고 계정·고지 준비가 된 뒤 한 공급원 파일럿으로 검토한다.

## 생활 서비스 연결

여러 앱을 모아 둔 링크 디렉터리는 차별점이 약하다. `사용자의 조건을 다시 입력하지 않고 다음 행동으로 넘겨 주는 것`이 연결의 가치다.

초기 카드에는 다음만 표시한다.

- 언제 필요한가
- 무엇을 비교해야 하는가
- 예상 입력 정보
- 공식 외부 링크와 책임 주체
- 완료 표시와 돌아올 다음 단계

초기 후보는 이사, 입주청소, 인터넷, 대형폐기물이다. 먼저 `service_interest`, `service_outbound`, `service_return`을 측정하고 가장 많이 반복된 한 종류만 제휴·예약 연결로 발전시킨다. 파트너 API/OAuth나 완료 이벤트가 없으면 단순 외부 링크로 분리한다.

## 벤치마크 우선 실행 순서

### 0. 채찍단형 탐색 골격 즉시 적용

- 39개 품목을 모바일 검색·카테고리·조건 필터·이미지 카드·상세 화면으로 탐색 가능하게 구성
- 기본순은 입주 시점과 조건 일치도를 사용하고, 실제 상품 근거가 없는 정렬은 노출하지 않음
- `생활 서비스` 영역도 탐색·비교 기준까지 먼저 공개

### 1. 계측 정리

- 프로덕션 외 트래픽과 운영자 사용을 제외
- `condition_select`, `comparison_open`, `product_detail`, `store_click`, `save`, `return_7d`를 확인
- 현재 관찰된 표본은 작고 GA 주요 이벤트가 설정되지 않아 성장 판단에 쓰지 않음

### 2. 깊은 상품 데이터 적용

- 세탁세제 8종만 수작업 이중 검증
- 실제 가격은 관찰 시각과 판매처를 함께 표시
- 세 조건별 추천 이유와 1회 사용비 제공
- 검색 의도 페이지 3개를 같은 비교 화면으로 연결

### 3. 출시 후 사용자 관찰

- 실제 첫 자취 준비자 5명 이상을 화면 공유로 관찰
- 관찰 결과는 출시 여부가 아니라 다음에 실제 상품 데이터를 채울 품목과 공급원 우선순위를 결정하는 데 사용
- 선택 완료율, 결정 시간, 선택 확신, 상품 상세·구매 클릭을 기록

### 4. 공식 공급원 1개

- 한 판매처/제휴 API만 연결
- 품절, 옵션, 배송비, 갱신 실패 처리부터 검증
- 공식 피드를 붙일 수 있는 품목은 사용자 표본과 무관하게 연결하되, 이후 행동이 낮은 품목은 갱신 비용을 줄임

### 5. 생활 서비스 연결 확대

- 사용자의 생활 조건을 재사용할 수 있고 공식 연결 경로가 있는 서비스부터 붙임
- 수요 데이터는 만들지 말지를 정하는 허가증이 아니라 어떤 서비스의 연결 깊이를 먼저 높일지 정하는 기준으로 사용

## 검색·유입 전략

상품 수를 늘리는 것만으로 검색 유입이 늘지는 않는다. 한 사용자의 구체적인 질문을 해결하는 색인 가능한 페이지가 필요하다.

- 원룸 실내건조 세탁세제 고르는 기준
- 운동복 땀냄새 세탁 기준
- 향에 민감한 자취생의 세제 선택 기준

각 페이지는 일반론으로 끝나지 않고 동일한 비교 데이터, 근거, 갱신 시각, 저장 기능으로 이어진다. 재방문은 무작위 품목 탐색보다 `저장한 계획`, `소진·가격 알림`, `이사 일정 다음 행동`에서 만든다.

## 즉시 결정

1. 채찍단의 모바일 탐색·비교 구조를 39개 전 품목의 공통 골격에 바로 적용한다.
2. 실제 상품 비교는 세탁세제 8종부터 깊게 채우고 이후 품목은 같은 데이터 모델로 추가한다.
3. 전 품목 스크래핑과 시장 전체 `인기/최저가` 약속은 하지 않되, 출처와 시각이 있는 확인 가격은 바로 제공한다.
4. 생활 서비스는 별도 영역의 탐색 구조를 먼저 만들고 공식 링크·제휴가 준비되는 대로 연결한다.
5. 쿠팡 파트너스 등 공식 공급원 준비는 사용자 표본을 기다리지 않고 병행한다. 가입·승인 전에는 외부 검색 링크와 수동 검증 데이터를 사용한다.

- 채찍단의 초기 유입 채널, 전환율, 잔존율, 매출 성장 원인은 공개 자료로 검증되지 않았다.
