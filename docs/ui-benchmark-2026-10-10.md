최종 v3 공개 흐름: 지역 검색/상세/복귀의 검색어·지역 유지=true. 지도는 robots_disallowed 중단 기록을 재사용해 최종 업체 동일성 미확인으로 남겼다. 상품 첫 화면 구매 CTA=true, 판매처는 HTTP 200이지만 제목이 일반 `Amazon.com`으로만 반환되어 정확한 옵션 확인으로 승격하지 않았다. 관찰 보고서 생성 성공과 과업 전체 검증 완료는 다르다. 기존 제품 전체 회귀 171개/SEO/66개 안내도 재실행해 통과했으며 제품 UI 자체는 변경하지 않았다.

[Playwright 공식 Route 문서](https://playwright.dev/docs/api/class-route#route-fetch)는 `maxRedirects: 0`일 때 자동 추적을 하지 않는 옵션을 설명한다. 새 정책은 문서 요청에 적용하며 임의 URL을 받는 보안 프록시나 모든 하위 리소스의 정책 준수를 보증하는 도구가 아니다. 실행 제한/중단은 요청량을 관리하는 경계이지 후보 사이트의 배제나 나쁜 UX 판정이 아니다.

### 설계에 반영할 차이

- 제품 CTA: 확인한 판매 옵션으로 직접 이동하는 행동과 검색 결과로 이동하는 행동을 다른 문구로 표시한다. 기존 홈 검사는 초기 상품 링크 210개 중 직접 1개/검색 209개였으므로 전체가 동일 상품 구매 링크인 것처럼 설계하지 않는다. 최신 가격/평점/후기 채널이 없으면 생성하지 않는다.
- 지도 CTA: [카카오 공식 가이드](https://apis.map.kakao.com/web/guide/)는 좌표/이름+좌표/장소 ID 경로를 구분한다. 상호+좌표 위치 핀과 실제 업체 상세를 구분하고, 확인한 장소 ID가 있을 때 업체 상세 이동을 약속한다. 주소 검색을 상세 이동처럼 숨기지 않는다.
- 앱 CTA: 서비스 설명과 이용 조건을 먼저 이해시키고, 업체 서비스/해당 지역의 공식 안내/iOS/Android를 목적에 맞게 표시한다. 없는 OS 링크는 미확인이지 앱 미제공으로 추론하지 않는다. 고객용·파트너용 앱을 혼합하지 않는다.
- 소개 화면과 실행 화면을 혼동하지 않는다. [런드리고](https://www.laundrygo.com/)는 업체/서비스 소개와 설치 연결을, [미소](https://miso.kr/)는 서비스 종류와 앱 연결을 확인했다. 홈페이지가 열린 사실로 설치·예약·주소별 이용 성공을 주장하지 않는다.

사용성 조사에서 수행과 만족을 분리하는 근거는 [NN/G 수행·만족 구분](https://www.nngroup.com/articles/satisfaction-vs-performance-metrics/)이다. 소수의 정성 관찰에서 전체 고객의 성공률/평균을 주장하지 않는 기준은 [NN/G 정성 조사 수치 해석](https://www.nngroup.com/articles/metrics-qualitative/)을 따른다. 이를 정확한 참가자 수나 임의 점수 컷으로 바꾸지 않는다. [Baymard 버튼 연구](https://baymard.com/blog/button-design)는 명확한 행동 구분에 참고하되 우리 화면의 선호/성과를 입증하지 않는다.

| 현상 | 사용자 첨부 15장과 로컬 코드: 분산된 필터, 상세 하단 구매 링크, 반복 경고, 큰 전체 건수, 원문 상호명, 영문 필드 | 전체 고객의 이탈 원인·이탈률·평균 선호 |
| 외부 화면 | 채찍단/오늘의집/쿠팡의 데스크톱 공개 DOM·화면 조사 | 모바일·로그인·모든 시점의 동일 UI, 특정 요소의 매출 효과 |
| 연구 | 아래 R1~R6의 일반적 연구·기준 | 제안한 색·간격·문구가 우리 고객에게 예쁘거나 쉬울 것이라는 확정 |
| 자사 데이터 | 기존 제품/업소 원장과 출처 존재, 일부 링크·규격 검증 | 모든 제품의 쿠팡 동일상품/현재 가격/평점/후기, 모든 업체의 현재 영업 |

공식 연구의 요지를 짧게 적용한다. 나머지 수치·배치는 **검토할 설계값**이지 연구가 지시한 정답이 아니다.

- R1 [Baymard 상품 목록 정보 연구](https://baymard.com/research-articles/product-listing-information): 목록에서도 상품을 평가할 핵심 정보가 필요하며 평점은 후기 수와 함께 해석해야 한다. 우리 목록의 정보 우선순위에 참고한다.
- R2 [NN/G 점진적 공개](https://www.nngroup.com/articles/progressive-disclosure/): 우선 필요한 정보와 세부 정보를 구분한다. 경고를 없애 사실을 숨기라는 근거가 아니다.
- R3 [시각 복잡성·전형성 연구, Tuch 등 2012](https://research.google/pubs/the-role-of-visual-complexity-and-prototypicality-regarding-first-impression-of-websites-working-towards-understanding-aesthetic-judgments/): 해당 실험에서 단순하고 익숙한 웹 화면이 미적 평가에 유리했다. 우리 화면 체류 증가를 입증하지 않는다.
- R4 [NN/G 미적 사용성 효과](https://www.nngroup.com/articles/aesthetic-usability-effect/): 외관 만족이 사용성 문제를 가릴 수 있다. 선호 질문과 실제 과업 검사를 따로 한다.
- R5 [W3C WCAG 2.2 표적 크기 AA](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum): 24×24 CSS px 또는 예외 조건을 정의한다. 이 설계는 주요 조작에 44px 이상을 제안하지만 이를 AA의 필수 44px라고 부르지 않는다.
- R6 [GOV.UK 페이지네이션](https://design-system.service.gov.uk/components/pagination/): 번호·현재 위치·생략·이전/다음, 좁은 화면 축약을 참고한다. 필터 변경은 전체 결과에 적용한 뒤 첫 페이지로 간다.

### 벤치마킹 후보와 적합성

유명도나 사이트 전체를 기준으로 복사하지 않는다. 과업 유사성/직접 확인 가능성/모바일 검증/정보 보유 수준/운영 복잡도를 각각 판단한다. 점수를 임의로 합산한 객관적 순위는 만들지 않는다. 후보는 아래 목록으로 고정하지 않는다.

| 후보 | 확인 범위 | 가져올 후보 패턴 | 그대로 가져오지 않을 부분 |
|---|---|---|---|
| 오늘의집 | 상품 목록 DOM·상품 상세 데스크톱 화면 | 사진·상품명·규격·평점/후기 근접 배치 | 영감 콘텐츠 피드, 자체 결제/쿠폰 체계 |
| 쿠팡 | 홈 HTML·수건 검색 DOM/화면 | 정확한 옵션, 총액/단위 가격 구분, 검색 중심 탐색 | 광고 밀도, 회원가를 일반가로 표시, 쿠팡 원문 없이 후기 복제 |
| 채찍단 | 홈 데스크톱 DOM/화면 | 비교 가능한 단위와 상품 간 차이 | 식품의 비교 단위를 가전/장소에 무리하게 확장 |
| Google Maps | 공식 장소 검색 도움말 | 장소·지역·업종의 검색 모델과 장소 정보 | 지도 전체를 첫 화면에 강제, 도움말 관찰을 실제 모바일 검증으로 표현 |
| Yelp | 공식 검색 도움말 화면, 실제 검색은 장치 확인으로 중단 | 지역과 키워드를 구분하는 원리 | 접근 못 한 결과 화면을 본 것처럼 채택 |
| GOV.UK | 공식 문서 HTML·번호 예시 화면 | 현재 페이지 강조·번호 이동·생략 | 정부 서비스의 외형 전체를 쇼핑 화면에 복제 |
| IKEA·다나와·노써치 | 과거 참고 기록만 존재 | 제품 규격·비교 검토 후보 | 이번 최신 화면을 재검증하지 않았으므로 현재 UI 사실로 단정 |
| 네이버지도·당근·Airbnb | 추가 조사 후보 | 지역 탐색/필터/직접 이동의 비교 대상 | 이번 직접 검증 전에는 채택 근거로 사용하지 않음 |

직접 확인 URL·관찰 한계·8개 적용 패턴은 비공개 `data/exports/ui-review-2026-10-19/benchmarks.md`에 있다. 외부 HTML은 구조 확인에 쓰고 스타일/코드/리뷰를 통째로 복제하지 않는다. 이번 조사만으로 최종 디자인 후보가 충분하다고 선언하지 않는다.

### 1. 공통 탐색 골격

대표 제안은 `상품 / 우리동네 / 생활 앱 / 저장`이다. **제안이며 최종 문구 미확정**이다. 내 준비표/계산기/조건 설문은 삭제하지 않고 주 탐색에서 한 단계 내리는 안을 검토한다. 저장은 상품·장소·앱을 보관하는 뜻이며 구매완료/보유 여부와 섞지 않는다.

- PC: 브랜드와 네 메뉴를 한 줄, 본문은 최대 1160px 제안. 현재 메뉴만 선·색과 aria-current로 구분한다.
- 모바일: 브랜드 헤더와 하단 네 메뉴. 본문과 같은 메뉴를 탭/칩으로 한 번 더 반복하지 않는다. 하단 영역 높이만큼 본문 여백을 확보하고 키보드·안전 영역을 검사한다.
- 홈 제목은 브랜드 또는 짧은 카테고리로 검토하고 큰 가치 제안·추천/비교 반복 문구는 우선 제외한다. SEO 제목/H1 실험에 영향이 있으면 별도 승인하고 문구만 임의 교체하지 않는다.
- 상품 검색과 장소 검색은 대상을 명시한다. 같은 검색어가 다른 데이터의 결과로 조용히 바뀌지 않는다.

### 2. 상품 첫 화면의 요소별 설계

390×844 CSS px를 대표 화면으로 삼되 안전 영역·기기 UI에 따라 가용 높이가 달라지므로 아래 크기는 보장값이 아니다. 사진/구매 버튼/첫 결과가 실제 화면에 함께 보이는지를 캡처로 확인한다.

```text
브랜드                                      저장
상품명·용도 검색                        검색 아이콘
전체   먹거리   주방   욕실   세탁   ...
현재 분류                         필터·정렬
사진          상품/품목 이름
              차이 1 · 차이 2
              확인된 가격/단위 또는 가격 생략
              출처 있는 평점·후기 또는 해당 행 생략
              [쿠팡에서 보기] 또는 정확한 판매처명
              비교/다른 제품은 보조 동작
다음 결과의 시작
```

| 요소 | 넣는 이유/근거 | 배치와 동작 | 넣지 않을 조건 |
|---|---|---|---|
| 검색 | 구체적인 물건을 아는 방문자의 직접 탐색 | 헤더 다음, 예시 검색어 1~2개, 엔터 제출. 이전 분류와 충돌하면 해제 사실을 표시 | 홍보 문구·온보딩으로 앞을 막지 않음 |
| 카테고리 | 물건 이름을 모르는 사람의 탐색 | 첫 단계는 같은 깊이의 생활 영역. 하위 용도는 선택한 영역 안에서만 공개 | 전체/먹거리 개수 배지, 서로 다른 분류 축 혼합 |
| 사진 | 제품 식별, R1 | 실제 모델/옵션 사진, 정사각형 contain, 고정 크기, 필요 시 같은 사진 확대 | 다른 제품 대체 사진·자동 과도한 크롭 |
| 이름·옵션 | 뭘 사는지 식별, R1 | 브랜드/모델·용량/수량을 구분. 긴 이름은 정해진 행 수로 요약하고 접근 가능한 전체 이름 제공 | 옵션·서로 다른 브랜드를 동일 상품으로 취급 |
| 특징 2~3개 | 상세를 열기 전 비교, R1 | 품목별 우선순위: 세제는 사용 세탁기/용도/용량, 냄비는 열원/용량/재질, 식품은 내용량/구성 등 | 제품명·기준 문구를 검증된 효능으로 바꾸지 않음 |
| 가격 | 구매 판단 | 실제 가격과 기준 단위를 분리. 시점·옵션·조건이 맞을 때만 | 만료 가격, 추정 최저가, 가격 없음=0원 |
| 평점/후기 | 경험 기반 정보, R1 | 점수/척도·후기 수·플랫폼·원문 링크를 한 묶음. 확인일은 보조 정보 | 데이터/권한 미확보면 별점 행 생략. 미확인을 0점이나 후기 0개로 표시하지 않음 |
| 주요 구매 CTA | 선택 후 이동 비용 줄이기 | 카드에서 바로 누르는 판매처명 버튼 1개. 같은 상품 쿠팡 링크가 검증된 경우 쿠팡 우선 | 쿠팡 검색 링크를 해당 제품 구매로 부르지 않음 |
| 비교/저장 | 구매 전 결정을 보조 | 주요 CTA보다 약하게. 저장 버튼은 44px 조작 영역, 원래 위치 복귀 | 구매 버튼과 같은 강조 버튼을 여러 개 나란히 두지 않음 |

**품목과 실제 상품의 단위를 먼저 확정해야 한다.** 현재 홈 213행은 제품 SKU 213개가 아니라 품목/안내 단위이며 내부 상품 수가 다르다. 이를 상품 카드처럼 보이게 하면서 버튼은 품목 검색으로 보내는 구조는 바꿔야 한다. 설계 후보 A는 홈 품목→선택한 품목 안의 실제 상품 카드, B는 검증된 상품을 홈부터 직접 노출하는 방식이다. 재구현 전에 원장 보유 범위와 첫 구매 과업으로 A/B를 비교한다. 자료가 풍부해 보이도록 옵션을 별도 모델로 늘리지 않는다.

### 3. 상품 상세/비교의 첫 화면

사진·이름·핵심 차이·구매 버튼이 첫 상품 블록 안에 있다. PC는 2~3열의 같은 높이 제품 블록, 모바일은 한 열의 압축된 블록을 우선 비교한다. 숫자만 늘리기 위해 가로 스크롤 안에 제품을 숨기지 않는다.

- 상품별 순서: 사진/이름 → 확인된 핵심 특징 → 가격/평점이 있을 때만 → 주요 CTA → 세부 규격 펼치기.
- 현재 상단 사진 모음, 모델 수 안내, 반복 경고가 구매 정보보다 먼저 높이를 차지하는 구조는 축소 후보다.
- 원래 상품과 유사상품 검색은 별도다. 정확한 쿠팡 URL이 없는 상품을 삭제하거나 쿠팡 판매품처럼 변환하지 않는다. 한 주요 CTA는 해당 상품의 검증된 판매처로, 다른 경로는 선택적으로 펼친다.
- 상세 규격 표의 식별자 `foodType`, `grain` 등은 한글 표시명으로 바꾸되 원본 key는 유지한다. 원문·출처는 선택적으로 열 수 있게 한다.
- 후기 요약은 실제 표본/플랫폼/시점/옵션이 연결되고 재사용이 허용된 뒤 별도 설계한다. 한두 리뷰를 전체 구매자 평가로 일반화하지 않는다.
- 모든 제품이 어떤 기기에서도 스크롤 없이 전부 보이는 것은 불가능하다. 목표는 첫 제품의 핵심과 구매 버튼을 스크롤 없이, 다른 제품은 일관된 최소 정보로 탐색하게 하는 것이다. 긴 원문과 모든 상세는 선택적 공개다.

### 4. 우리동네 첫 화면의 요소별 설계

```text
브랜드                            우리동네 선택됨
구 선택             동 선택
업종 선택           선택한 업종의 세부 종류
상호명·장소 검색                    검색
선택 조건 / 지우기
상호명                                      저장
실제 업종/기능 한 줄
주소
[위치 보기]  등록 장소가 검증되면 [장소 상세]
다음 결과
이전     1  2  3  ...                다음
데이터 출처 (선택적으로 펼침)
```

| 요소 | 이유 | 정밀 규칙 |
|---|---|---|
| 구→동 | 요청한 지역을 명확히 한정 | 구 변경은 동 초기화, 법정동을 기본으로 사용. 행정동 전환은 고급 옵션으로 숨기되 현재 선택은 보임. 전체 서울 허용, 위치 권한 필수 아님 |
| 업종→하위 업종 | 무엇을 하는 곳인지 구체화 | 현재 21대분류만으로 음식점/주점/간식점 등을 구별할 수 없다. 원본 중·소분류를 재사용하고 정의된 부모 아래에서만 선택. 상호명으로 업종/취급 품목을 추정하지 않음 |
| 검색 | 특정 업체·장소를 아는 방문자 지원 | 지역/업종과 AND 적용. 조건 바뀌면 첫 페이지, 검색 중에는 이전 조건의 결과를 새 결과처럼 표시하지 않음 |
| 상호명·설명 | 상세를 눌러야 의미를 아는 문제 방지 | 원본 업종은 업종 설명으로, 확인된 업체 기능은 업체 설명으로 구분. 소개가 없으면 업종명만 보이고 없는 소개를 생성하지 않음 |
| 주소·이동 | 한 번에 목적지로 연결 | 주소는 목록에 표시. 이름+주소를 검색어로 조합하지 않음. 좌표 링크는 상호명 핀 위치이며 등록 업체 상세/후기와 구분 |
| 등록 장소 연결 | 동명이점·빈 검색 감소 | 카카오 place ID/URL이 업체명·주소·좌표로 식별된 경우만 상세 직링크. 여러 후보/폐업/불일치는 보류. 원본 상가 ID를 카카오 ID로 사용하지 않음 |
| 평점/후기 | 장소 판단 보조 | 카카오 Local 응답에는 평점/후기 필드가 없다. 별도 허용 데이터 없이는 표시하지 않음. 지도 상세에서 직접 보는 경로와 우리 사이트에 복제하는 것은 다름 |
| 번호 이동 | 한 칸씩 넘기는 부담 감소 | PC는 연속 번호와 첫·끝·생략, 모바일은 주변 번호 유지. 현재 번호는 aria-current. 필터/지역/검색은 뒤로 가기·새로고침 후 복원 |
| 출처·기준일 | 근거 추적, R2 | 목록 상단의 긴 반복 문구 대신 하단 펼치기/데이터 정책. 기준일과 확인일을 분리하며 최신/영업중이라고 오인시키지 않음 |

정렬은 사용자에게 의미 있는 기준으로 정해야 한다. 현재 원문 가나다순은 특수기호 업체를 먼저 모으는 부작용이 있다. 정규화한 표시명 가나다순을 후보로 검토하고, 거리순은 기준 위치와 계산 방법이 있을 때만, 평점순은 실제 동일 플랫폼 평점이 있을 때만 제공한다. 기본 인기순을 만들어 내지 않는다.

### 5. 생활 앱과 저장

- 생활 앱은 우리동네와 분리된 메뉴 후보다. 전국 온라인 서비스에 구·동 선택을 강제하지 않는다. 앱 카드는 이름·하는 일 한 줄·확인된 공식 웹/OS 링크를 목록에서 제공한다. 비용/지역 조건은 필요한 상세로 내린다.
- 저장은 처음 비어 있어야 한다. 기존 상품 저장과 서비스/장소 저장은 종류를 유지하면서 한 입구에서 `상품 / 장소 / 앱`으로 볼 수 있게 하는 안을 검토한다. 저장 수를 보유·구매 수로 표현하지 않는다.
- 내 준비표는 기존 사용자 자료를 삭제하지 않는다. 홈의 주 메뉴/주 CTA에서 내려갈지 별도 승인하며 저장과 합칠 때도 이관/원복 검사를 한다.

### 6. 시각 설계 후보와 규격

시각 후보 A는 흰 바탕+절제된 녹색 강조의 정보형, B는 상품 사진이 더 큰 쇼핑형이다. 현재 선택되지 않았다. 먼저 같은 실제 상품·문구·정보량으로 두 로컬 시안을 만든다. A/B가 다른 상품이나 더 좋은 사진을 쓰면 화면 선호 비교가 오염된다.

- 공통 후보값: 본문 16px/행간 1.5~1.7, 보조 14px, 카드 제목 18~20px, 화면 제목 24~28px. 뷰포트 비례 폰트나 거대한 히어로 문구는 사용하지 않는다.
- 4/8px 간격 체계, 모바일 좌우 16px, 블록 간 24px, 카드 내부 12~16px부터 검토한다. 카드 반경은 4~8px. 숫자는 시험할 시작값이지 최적값 근거가 아니다.
- 한 영역 주요 행동 1개, 보조는 링크·아이콘. 선택/성공/오류는 색만으로 구분하지 않는다. 단순 아이콘에 툴팁·접근 가능한 이름을 붙인다.
- 표·드롭다운·본문·큰 사진을 카드 안의 카드로 쌓지 않는다. 상위 섹션은 프레임 없이, 반복되는 실제 상품에만 경계를 사용한다.
- 320/390/768/1024/1440px, 가로 회전, 200% 확대와 긴 이름을 검사한다. PC를 좁은 모바일 프레임으로 강제하지 않는다.

### 7. 검증: 취향과 사용성을 따로 측정

아래는 **제안한 사전 기준**이다. 현재 사용자 검사를 한 것이 아니고, 작은 정성 표본으로 전체 고객 효과를 계산하지 않는다.

1. 같은 내용의 A/B 시안을 순서 교차 배치한다. 첫 화면을 본 뒤 서비스 목적을 설명하게 하고 첫 클릭 위치를 기록한다. 예쁘다는 질문으로 유도하지 않는다.
2. 구매/자취 경험이 다른 참여자 5~8명 정도를 첫 정성 회차로 모집하는 안을 제안한다. 인원은 통계적 효과 검증에 충분하다는 뜻이 아니다. 모바일 중심으로 시작하되 PC 과업도 포함한다.
3. 실제 과업: 인덕션용 1~2인 냄비 찾기, 운동복 세제의 차이 확인 후 구매처 이동, 강남구 신사동 세탁 관련 업소 찾기, 5페이지 직접 이동 후 필터 변경, 저장 후 재방문. 동명이점·빈 결과·링크 실패를 포함한다.
4. 기록: 무도움 성공/실패, 첫 클릭, 완료 시간, 되돌아가기/재검색, 오클릭, 말로 설명한 혼동, 실제 외부 목적지 일치. 링크를 눌렀다는 것과 구매/예약 완료를 구분한다.
5. 사후에 선호와 이유를 별도로 묻는다. 관찰 과업이 실패했는데 예쁘다는 평가만 좋으면 통과시키지 않는다. 기본 데이터/평점 부재에 대한 불만도 디자인 문제와 분리해 기록한다.
6. 1차 통과 조건 제안: 핵심 링크 오연결·가짜 평점·데이터 손실·접근 불가 0건. 반복 혼동이 나온 항목은 수정 후 재검사한다. 시간/전환 개선율의 숫자 목표는 기존 화면 기준선 측정 전 임의로 정하지 않는다.
7. 실제 배포 후 전환/재방문 판단은 충분한 관측량과 같은 이벤트 정의가 확보된 비교에서만 한다. 체류 시간이 길어진 것을 무조건 성공으로 보지 않는다.

## 이미지·링크 처리

- 기존 213개 품목 / 215개 상품 후보 / 공식 안내 3개 범위는 유지했다.
- 실제 상품 이미지 URL은 132개에서 215개로 채웠다. 누락 83개뿐 아니라 원래 있었지만 브라우저에서 실패한 사진도 대체 출처를 확인했다.
- 상품명·모델·용량·묶음 수량을 확인했다. 여러 옵션을 함께 보여 주는 사진은 `옵션 대표 이미지`라고 표시한다.
- 제조사·판매처의 공개 상품 자료를 사용하며, 차단·보안 확인을 우회하지 않았다. 공개 이미지의 표시 확인이 장기 사용권·제휴 계약 확보를 뜻하지는 않는다.
- 홈페이지로 이동하던 오래된 링크, 다른 모델 사진, 판매 옵션과 맞지 않던 규격을 정정했다. 최신 가격·재고·배송은 판매처에서 확인한다.
- 대화 원문과 내부 출처 검토 기록은 비공개 `data/exports/`에 유지한다.

- 저장 시 카드 전체를 다시 그리지 않아 사진 재로딩과 포커스 이동을 줄인다.
- 선택한 필터를 개별 해제할 수 있고, 정렬·필터는 URL로 복원한다.
- 상세 창에서 사진·제품 규격·판매처를 앞세운다. 닫으면 원래 카드와 스크롤 위치로 돌아간다.
- 저장 완료·실패 알림, 링크 복사, 맨 위로 이동, 초기 이미지 우선 로딩을 제공한다.
