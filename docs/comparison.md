# 상품 비교 계약
2026-10-13 통합. 기존 비교 설계·UX·구현·미래 가격 제안을 대체한다. [현재 상태](current-work.md), [개선 제안](next-actions.md), [참고 역할](benchmark-register.md)은 별도 단일 문서를 따른다.

## 비교 단위
분류 → 품목 → 같은 목적·필수 조건 → 모델 → 판매 옵션 → 판매처.
- 비교군 요구는 기준 1+대안 5, 그룹당 서로 다른 모델 6개 목표로 해석했다. 사용자 변경 가능하며 기준 제품은 자동 1위가 아니다.
- 색상·향·묶음·리필·판매처/설치 옵션만으로 모델 수를 부풀리지 않는다. 기존 ID를 재번호 매기지 않는다.
- 드럼/일반·식품 유형·침구 규격 등 목적/호환을 먼저 구분한다. 필수 조건 미확인을 적합 제품으로 추천하지 않는다. 공식 안내 3개는 쇼핑·수량 예외다.
- 부족한 후보는 있는 그대로 제공하고 전체 큐를 유지한다. 수량·이름/옵션/사진/링크·핵심 규격·권한·UX·구매 효과를 별도 상태로 관리한다.

## 자료 계약
| 구조 | 필드/의미 |
|---|---|
| 품목/그룹 | 영속 id, 목적·필수 조건·목표 수·attributeDefinitions |
| 모델/옵션 | 영속 id·modelKey, 제품명, 정확한 URL/사진, 중복/적합 상태 |
| 속성 | 값·단위·verified/unknown/not_applicable, 근거 유형·URL·시각·적용 범위 |
| 가격 관측 | 정확한 옵션, 일반가·배송·회원/쿠폰, 확인/만료 시각; 규격과 분리 |
| 차이 | 동일 조건/단위의 실제 값 차이, 사실/계산/추론·선택 영향·한계·출처 |

- 미확인·0·없음·불가·해당 없음을 구분한다. 단위 불일치·조건부·충돌은 우열 계산에서 제외한다. 선호·선택 기준·후기로 제품 사실을 만들지 않는다.
- facts는 호환 원문이며 상세 저장 한도가 아니다. 핵심 항목을 별도로 정의하고 전체 원문을 유지한다. 계산은 코드로 하며 다른 모델/배합의 시험 결과를 붙이지 않는다.
- 제조사 표기·판매 관측·후기·독립 시험을 구분한다. 효과·항균·건강·안전·전기요금을 임의 추론하지 않는다. 큰 숫자를 자동 우수로 칠하지 않는다.
- 열원은 출처의 명시적 독립 문장만 가능/불가로 분류하고 조건부·충돌은 미확인. 인분/인용은 명시 필드·확인 제품명만 쓰며 리터/후기로 환산하지 않는다.
- 동일 상품의 화면별 통일은 미완료다. 모델/옵션/출처 ID를 확인해 연결하며 충돌을 최신 값처럼 덮지 않는다.

## 품목별 선택 정보
| 분류 | 먼저 확인할 항목 |
|---|---|
| 먹거리 | 내용량·묶음·원재료/영양/알레르기·보관·조리·소비기한 |
| 주방 | 치수·용량·소재·구성·열원/전자레인지/냉동/세척 |
| 욕실·위생 | 내용량·제형·향·사용 대상·규격·교체·주의 |
| 세탁 | 세탁기/의류 호환·권장량/조건·용량·성분·향·시험 |
| 청소·폐기 | 표면/용도·희석/사용량·내용량·도구 규격·주의 |
| 침구·가구 | 실측·소재/충전재·세탁/건조·구성·설치/개폐 여유 |
| 가전 | 용량·설치 치수·전원·효율/기능·소모품·보증·측정 조건 |
| 수납·도구 | 외부/내부 치수·하중·개폐/고정·재질·구성·호환 |
| 환경·안전 | 대상/공간·전원/설치·수명·인증 범위·주의 |

품목/용도별 실제 우선순위는 comparison-display.js의 프로필을 따른다. 선택 기준을 상품 사실로 쓰지 않는다.

## UI·저장
- 사진 중심 후보 탐색, 목적이 여러 개일 때만 선택기. 실제 확인값의 최대 두 조건으로 정확 일치 AND 필터. 숨겨진 선택은 삭제하지 않는다.
- 확인한 쿠팡 /vp/products/<id>는 정확한 옵션 그대로, 다른 출처는 제품명 검색을 쿠팡에서 찾기로 구분한다. 검색 성공·동일 제품 판매·재고를 보장하지 않는다.
- 홈/상세 4행, 후보 6행, 비교 헤더 4행. 구매 버튼은 비교 제품명 다음. 긴 값은 80자 부분 표시+원문 전체, 전체 규격/출처/시각은 보존한다.
- 두 선택+비교 실행, 최대 4개 모델. 모바일 기본 2개와 전체 명단/현재 쌍·사진 전환, PC는 선택 3~4개 펼치기. 320px에서는 필요시 카드 1열, 44px 터치 영역·고정 요소 여백 유지.
- 같은 모델 옵션은 카드 안에서 고르고 교체 확정에 정확한 ID/사진/링크 적용. 저장/공유 비교는 바로 복원하며 출처 펼침·교체에서 위치/선택을 유지한다.
- 품목 저장과 비교 키는 별개. 비교는 jachi:comparison-products:v1 단일 기록·고정 30일 TTL, 읽기로 연장하지 않는다. 여러 비교 보관은 제안이다. 예산/상황 저장의 별도 정책과 섞지 않는다.

## 가격·수집
- 기본순은 편집/등록 순서다. 같은 유형/규격 안에서만 100g/100mL/1개/1회 비용 계산. 묶음·권장 사용량/조건을 확인하고 시험 비용에서 사용량을 역산하지 않는다.
- 기존 가격의 24시간 TTL은 내부 노출 한도이지 보장 기간이 아니다. 만료 가격/단가는 숨기고 정확한 링크·사용자 계산은 유지한다. 현재 자동 가격 갱신은 없다.
- 연동은 허용 데이터·정확한 옵션·갱신 운영·광고/수수료 고지·실패 대응을 승인 범위에서 설계한다. 키는 서버 환경변수에만 둔다. 과거 API 가용성 문구는 실제 연결 전 다시 확인한다.
- 검색 목록은 발견용. 동일 목적·상세·사진·규격 확인 전 적합 후보로 승격하지 않는다. robots/제공 조건을 확인하고 CAPTCHA·401/403/429 우회 금지, 실패/5xx는 보수적으로 중단·기록한다.
- 채팅·참여자·인증·캐시·큐는 비공개 data/exports/에만 둔다. 공개본은 안전한 구매 근거만 제공한다. 사진 로드 성공은 이용권·장기 가용성 증명이 아니다.

## 코드·재현
| 경로 | 역할 |
|---|---|
| comparison-core.js | ID/중복·선택·단위·가격 만료·저장 검증 |
| comparison-display.js | 프로필·원문·차이·호환·쿠팡·필터 |
| comparison-loader.js / comparison-index.js | 목록+품목 요청, 중복 캐시·재시도 |
| assets/comparison/Pxxx.json | 품목의 그룹·상품·속성 |
| catalog.js / comparison.js | 홈/상세/관련 상품·비교 UI |
| product-catalog.js / comparison-summary.js | 기존 홈 후보·작은 요약; 정합 후속 대상 |
| comparison-data.js | 전체 호환/검사 자료; 진입에서 읽지 않음 |
| scripts/plan-comparison-coverage.mjs | 전체 부족 큐/연결 집계 |

입력 변경 때만 npm run comparison:build. 목록 약 42.6KB+냄비 JSON 약 68.2KB는 비압축 자료 크기이며 체감 속도/전체 전송량 실측이 아니다.
