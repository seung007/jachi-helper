# Stage 1 구매 결정 성장 루프

작성일: 2026-09-02

## 1. 이번 단계의 목적

거시 목표는 계약부터 다음 이사까지 이어지는 주거 생활 실행 시스템이다. 그러나 현재 제품에서 먼저 증명할 것은 아래 한 문장이다.

> 첫 자취 사용자가 보유품과 생활 조건을 선택하면, 살 물건과 미룰 물건을 실제로 결정하고 판매처 확인까지 이어 간다.

Stage 1은 상품 추천 정확도나 제휴 매출을 증명하는 단계가 아니다. 사용자가 긴 설명 없이 결정을 끝내고, 저장된 계획을 다시 사용하는지 확인하는 단계다.

## 2. 현재 사용자 흐름

`검색·직접 방문 -> 홈 미리보기 -> 구매 계획 시작 -> 보유품 제외·생활 조건 선택 -> 결과 확인 -> 필요함·이미 있음·나중에 결정 -> 판매처 검색 -> 저장된 계획 재방문`

현재 구현된 핵심 상태는 다음과 같다.

- 구매 계획은 마지막 수정부터 30일 동안 이 기기에 저장한다.
- 저장된 계획이 없으면 결과를 임의 생성하지 않고 시작 화면을 보여 준다.
- 실제 상품 가격, 재고, 배송, 인기순은 추정하지 않는다.
- 사용자가 `필요함`, `이미 있음`, `나중에`를 직접 결정한다.

## 3. Stage 1 범위

### 포함

- 보유품 제외
- 생활 조건 세 가지 선택
- 선택 이유가 보이는 준비물 정리
- 품목별 구매 상태 저장
- 검증 가능한 판매처 검색 이동
- 빠진 항목·불필요한 항목 피드백
- 30일 안의 계획 이어보기

### 제외

- AI가 생성한 상품·가격·순위
- 통합 최저가와 재고 비교
- 제휴 수익에 따라 바뀌는 추천 순서
- 이사·청소 업체의 견적 또는 예약 완료 약속
- 계약·법률·예산 감당 가능성 판단

## 4. 측정 이벤트와 계산식

현재 코드의 이벤트 이름을 그대로 사용한다. 새로운 이름을 추가하기 전에 기존 이벤트의 사용자 수 기준 집계를 먼저 확인한다.

| 질문 | 이벤트 또는 상태 | 계산식 |
|---|---|---|
| 홈이 계획 시작을 만드는가 | `home_cta_click`, `plan_start` | 계획 시작 사용자 / 홈 순사용자 |
| 시작한 사용자가 끝까지 가는가 | `plan_complete` | 완료 사용자 / 시작 사용자 |
| 결과가 결정을 만드는가 | `recommendation_decision` | 한 개 이상 결정한 사용자 / 결과 조회 사용자 |
| 결정이 외부 행동으로 이어지는가 | `store_click` | 판매처를 연 사용자 / `필요함`을 남긴 사용자 |
| 결과가 현실과 맞는가 | `recommend_feedback` | 도움·누락·불필요 사유별 사용자 비율 |
| 계획이 다시 쓰이는가 | 저장 상태와 재방문 | 계획 완료자의 7일·30일 재방문 비율 |

이벤트 횟수 합계는 같은 사용자의 반복 클릭으로 부풀 수 있으므로 의사결정에는 순사용자 수를 우선한다.

## 5. 검증 방법

1. 2026-08-28에 잡은 유입·전환 기준선 실험이 끝날 때까지 홈 구조와 핵심 문구를 추가 변경하지 않는다.
2. 초기 사용자 최소 5명의 화면 사용을 관찰한다. 이 수는 통계적 증명이 아니라 치명적인 혼란과 누락을 찾기 위한 최소 발견 표본이다.
3. 각 사용자에게 완료 여부뿐 아니라 실제로 뺀 물건, 구매 후보, 보류 항목, 판매처 이동 이유를 확인한다.
4. GA4에서는 이벤트 수가 아니라 단계별 순사용자와 이탈 위치를 비교한다.
5. 누락·불필요 피드백이 반복되는 품목만 데이터와 문구를 수정한다.

## 6. Stage 2 진입 게이트

다음 조건을 확인하기 전에는 서비스 카테고리를 여러 개 추가하지 않는다.

- 홈부터 결과까지의 이벤트가 중복 없이 이어진다.
- 관찰 사용자들이 설명 없이 구매 상태를 남길 수 있다.
- 판매처 이동 또는 보류 결정처럼 결과 이후 행동이 확인된다.
- 반복된 누락·불필요 문제를 수정해도 핵심 흐름이 유지된다.
- 7일 또는 30일 재방문이 발생하는지 측정할 수 있다.

## 7. Stage 2 후보를 고르는 기준

첫 서비스 연결은 입주청소·이사·인터넷·폐기물을 동시에 만들지 않는다. 아래 기준으로 한 개만 선택한다.

| 기준 | 확인 질문 |
|---|---|
| 긴급성 | 놓치면 사용자의 시간·비용·스트레스가 실제로 커지는가 |
| 입력 재사용 | 입주일·지역·주거 형태 등 이미 받은 조건을 다시 쓸 수 있는가 |
| 비교 가능성 | 가격 외에도 서비스 범위·취소·후기·책임 기준을 설명할 수 있는가 |
| 공급 검증 | 연결처의 사업자·서비스 지역·연락·책임 정보를 확인할 수 있는가 |
| 실행 추적 | 링크 클릭이 아니라 상담·예약·완료 여부를 확인할 방법이 있는가 |
| 책임 위험 | 잘못 연결했을 때 발생하는 손해와 분쟁 범위를 감당할 수 있는가 |

Stage 2의 첫 화면은 서비스 목록이 아니라 `어떤 도움이 가장 급한가`를 확인하는 수요 검증이어야 한다. 실제 요청이 모인 한 카테고리만 연결 실험으로 전환한다.

## 8. 이번 단계의 완료 조건

- 기존 구매 결정 루프가 자동 검증을 통과한다.
- GA4에서 단계별 순사용자를 확인할 수 있다.
- 최소 5명의 관찰 기록과 누락·불필요 사유가 남는다.
- Stage 2 후보 한 개를 선택할 근거가 생긴다.

이 조건을 충족하면 다음 구현은 `입주일·지역·주거 형태 입력 재사용 -> 한 서비스 수요 확인 -> 검증된 연결처 제공 -> 상담·완료 상태 기록` 순서로 진행한다.
