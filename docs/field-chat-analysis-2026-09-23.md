# 자취 단톡방 91일 대화 분석

> 필요시 읽는 당시 근거/검토 기록이다. 최신 상태는 [현재 작업](current-work.md), 방향·실행 규칙은 [제품 방향](product-vision.md)과 [AGENTS](../AGENTS.md)를 따른다. 아래 제안·실험 문턱·당시 승인·집계는 현재 명령이나 새 작업의 승인으로 재사용하지 않는다.

> 2026-09-26 재검토: 아래 초기 분석의 건조기 사례 r005는 반복 질문을 흉내 낸 문맥으로 확인돼 직접 수요 근거에서 제외했다. 추가 표본 검토와 제품 우선순위는 [제품 기회 재분석](chat-product-opportunities-2026-09-26.md)을 우선 참고한다.

## 자료와 방법

- 자료: 사용자가 제공한 `자취.txt`(2026-06-25~09-23). 원본은 로컬에서만 읽었고 저장소에 복사하지 않았다.
- 91개 날짜, 168,920개 텍스트 줄, 시각과 닉네임이 붙은 메시지 약 159,120개를 확인했다. 닉네임 241종은 **고유한 사람 241명**이라는 뜻이 아니다.
- 질문 부호와 질문 표현으로 6,645개 메시지를 1차 선별하고, 그중 946개에 계약·주거비·이사·고장·집안일·가구/가전 중 하나 이상의 탐색 태그를 붙였다. 자동 선별은 농담, 답변, 다른 주제의 대화를 포함하고 한 질문이 여러 범주에 걸친다. 따라서 이 숫자를 수요량이나 우선순위로 사용하지 않았다.
- 6개 주제에서 기간 전체에 걸쳐 질문 사례를 직접 확인하고 17건을 수동 검토 데이터로 남겼다. 아래 사례는 분석자가 선택한 **정성 사례**이며 전수 코딩, 참여자별 추적, 구매·해결 결과 확인은 아니다. 줄 번호는 이 로컬 원본의 위치다.
- 닉네임, 상세 위치, 예산·소득 원문, 대화 원문, 채팅 링크는 이 문서에 옮기지 않았다. 채팅 속 답변을 검증된 생활·법률 지침으로 취급하지 않는다.

## 재사용 가능한 비공개 데이터

`npm run research:chat -- "C:/Users/user/Desktop/자취.txt"`로 원본 해시별 데이터셋을 재생성한다. 이번 산출물은 Git에서 제외된 `data/exports/chat-research-8f5d54b60924/`에 있다.

- `manifest.json`: 원본 SHA-256, 기간, 레코드 수와 자동 분류 범위.
- `messages.private.jsonl`: 전체 159,120개 메시지의 날짜·시각·원본 줄 번호·가명 화자 ID·본문. **본문에 개인정보가 남아 있을 수 있어 공개하거나 커밋하지 않는다.**
- `question-candidates.jsonl`: 6,645개 자동 질문 후보의 메시지 ID·주제·의도 검색 인덱스. `reviewStatus=auto_unreviewed`이며 확인된 수요가 아니다.
- `reviewed-needs.jsonl`: 최초 검토한 17개 레코드의 결정·조건을 익명으로 재기록했다. 2026-09-26에 r005는 문맥을 다시 확인해 직접 수요에서 제외했다. 나머지 레코드의 구매·해결 결과는 `not_verified`이며, 17개 전부를 확인된 수요라고 세지 않는다.

모든 레코드는 `messageId`로 연결된다. 원본이 없어져도 비공개 데이터셋에서 다시 검색·재분류할 수 있다. 단, 자동 태그와 닉네임별 메시지 수를 고객 수요 순위로 바꿔 쓰려면 중복 질문 및 문맥을 추가로 검토해야 한다.

## 우리 제품에 대한 판단

1. **준비물 링크만으로는 부족하다.** 구체적인 제품 추천 요청도 있지만, 그 직전에 사용자는 보유품·예산·세탁 가능 여부 같은 조건을 설명한다. 현재 `이불` 안내는 보유 여부·크기·계절을 확인하라는 문구를 제공하지만, 이 사례에 나온 세탁기 크기와 관리 부담을 입력받아 분기하지 않는다(`app.js`의 `bedding-duvet`). 상품명·최저가만 추가하면 문제의 일부만 해결한다.
2. **오늘의집은 '관심을 만드는 화면', 자취도우미는 '현실 조건으로 결정하는 다음 단계'로 구분할 수 있다.** 실제 대화에서 영감을 얻은 뒤 수납 현실을 다시 따진 사례가 있다. 한 사례만으로 이 흐름이 보편적이라고 주장하지는 않는다.
3. **생활 서비스 연결은 실제 질문과 맞닿아 있다.** 청소·용달·폐기 방법은 단순 쇼핑 링크로 해결되지 않는다. 다만 업체 품질, 견적, 지역 제공 범위를 검증하지 못했다면 비교·예약을 제공한다고 표현해서는 안 된다.
4. **입주 후 문제는 재방문 가설을 준다.** 곰팡이·세탁기·쓰레기처럼 반복적으로 발생할 수 있는 주제가 보인다. 이것이 실제 서비스 재방문을 만든다는 증거는 아니므로, 입주 전 14일 범위를 당장 전면 교체할 근거로 삼지 않는다.
5. **계약·대출·지원은 질문이 있어도 자동 판정 영역이 아니다.** 시기·지역·계약 조건에 따라 달라진다. 현재 제품의 `안내` 단계에서는 확인할 자료와 공식 문의처를 연결하고 개인별 법률·재정 결론을 단정하지 않는다.

## 권장하는 작은 실험

아래는 2026-09-23의 초기 제안이다. 2026-09-26 재검토에서는 이불을 단독 제품 우선순위로 확정하지 않고, 입주청소와 함께 공통 의사결정 흐름을 검증하는 사례로 재배치했다.

**첫 실험: 이불 한 품목의 조건 기반 결정 화면.** 기존의 39개 품목 전체를 다시 만들기 전에, 이미 질문이 구체적이고 현재 제품에도 있는 이불을 고른다. 보유 여부, 침구 크기, 세탁기 용량 또는 빨래방 이용 가능성, 예산을 묻고 `차렵/커버 분리형`의 관리·비용 차이와 구매 전 확인할 규격을 보여 준다. 검증된 상품 데이터가 없으면 가격·인기순·이미지를 꾸며내지 않고 해당 조건의 판매처 검색으로 이동시킨다. 성공은 링크 클릭만이 아니라 사용자가 선택을 저장했는지와 선택 이유가 도움이 됐는지로 확인한다.

**다음 후보: 청소·용달·폐기의 실행 경로.** 각 질문에 필요한 정보, 직접 처리와 외부 서비스의 차이, 이동 전 확인 사항을 한 화면에 모은다. 파트너 연동 전에는 신청·예약 완료처럼 보이게 하지 않는다.

**별도 검증: 생활 문제 대응.** 누수·곰팡이 같은 문제는 안전, 제조사 안내, 책임 주체를 검증한 뒤 안내해야 한다. 임의의 채팅 답변으로 해결 순서를 만들지 않는다.

## 이 자료로 아직 주장할 수 없는 것

- 최저가·인기순 정렬이나 실시간 할인 알림이 우선 기능이라는 결론
- 특정 상품 또는 업체의 품질, 가격, 재고, 안전성
- 이 기능을 만들면 유입·체류·구매·재방문이 증가한다는 인과 효과
- 단톡방의 질문 비율을 전체 자취생의 수요 비율로 일반화한 수치

다음 확인은 이불 한 품목의 실제 사용 테스트, 현재 사이트의 `store_click` 이후 구매 결정 인터뷰, 다른 채널의 유사 질문 비교다. 원문 문구를 홍보글이나 검색 콘텐츠에 그대로 재사용하지 않는다.
